# FineDroid

FineDroid is an LLM-driven pipeline for detecting non-crashing functional (NCF) bugs in Android UI interaction traces. Its four modules can be run in sequence or used independently with the released intermediate artifacts.

![FineDroid pipeline](overall4.png)

```text
01_NCF_Bug_Report_Collection/          # Step 1
02_Trace_Pair_Dataset_Construction/    # Step 2
03_Fine_Tuning/                        # Step 3
04_Post_Processing_Verification/       # Step 4
Evaluation/                            # Released evaluation results
artifacts/                             # Local generated/downloaded files
```

Each method module is a complete project with one entry command:

```bash
python3 01_NCF_Bug_Report_Collection/run.py
python3 02_Trace_Pair_Dataset_Construction/run.py
python3 03_Fine_Tuning/run.py
python3 04_Post_Processing_Verification/run.py
```

These commands run one module at a time; there is no root command that automatically runs all four modules.

Modules may be skipped as complete units. The clone already contains the released Step 1 filtered-report archive and the released Step 3 training datasets. Therefore, the Step 2 runner can start from the tracked Step 1 output, and the Step 3 runner can start from the tracked final training dataset. To skip fine-tuning, download the released LoRA adapter and place it at `artifacts/models/finedroid-qwen3-14b/` as described in the Step 4 README.

See each module README for its overall input, output, credentials, and single run command:

- [NCF Bug Report Collection](01_NCF_Bug_Report_Collection/README.md)
- [Trace-Pair Dataset Construction](02_Trace_Pair_Dataset_Construction/README.md)
- [Fine-Tuning](03_Fine_Tuning/README.md)

## Google Drive artifacts

Large released outputs and convenient archive mirrors are in the [FineDroid Project Data folder](https://drive.google.com/drive/folders/1Gcd3DOvtz2brau-ETGziX9KAn1119fgM?usp=sharing):

- `all_issues_new.zip` is the complete GitHub issue corpus produced by the Step 1 crawler. It is an optional snapshot for inspecting or re-filtering the original crawl; a fresh Step 1 run can regenerate it.
- `fine-tuned_qwen3-14b.zip` is the LoRA adapter produced by Step 3. Download it only when Step 3 is skipped and Step 4 should run the released model.
- `testingset.zip` contains the APKs, screenshots, UI hierarchy XML files, and traces saved while executing the evaluation cases. The compact final test-set representation is tracked under `Evaluation/test_set/`; this archive supplies the larger raw execution evidence.
- `detector_images.zip` contains the 100 detector input images generated by the VisionDroid re-implementation from those evaluation screenshots, UI hierarchies, and recorded actions. It is evaluation evidence rather than an input to the four FineDroid modules.

To reproduce the released evaluation tables without running the model:

```bash
python3 Evaluation/reproduce_tables.py --check
```

Source code, comments, documentation, prompts, and file names are English/ASCII. Published research data may retain multilingual Android UI text, bug reports, raw model responses, and human review notes because translating them would change the training data or audit evidence. Image and video contents are not normalized.
